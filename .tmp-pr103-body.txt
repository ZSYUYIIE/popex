## Public or integration contract

### Canonical per-event warnings

Canonical raw pitched events accept up to ***128 warnings per event, each up to 500 characters***. Harmony inference and artifact validation now accept that same safe envelope and preserve warning order, duplicates, empty lists, and text exactly while retaining hostile path/URL/credential/control/HTML rejection.

For newly generated harmony the path is:

```
canonical raw pitched warnings
… infer_harmony(...).raw_evidence[].warnings
… schema-1 rawEvidence[].warnings
… attempt-scoped publication + reload
… API freshness comparison
… full details + JSON download
```

### Genuine legacy schema-1 warning compatibility

For the durable legacy pointer ***`harmony/harmonic-context.json` only***, a `rawEvidence` item that physically lacks the `warnings` field means the old schema-1 artifact did not persist warning provenance. The loader preserves that missingness rather than fabricating `[]`; HTTP freshness compares every other canonical field exactly and may serve the validated legacy artifact even when the current raw has warnings.

An explicitly stored `warnings: []` is different from a missing field. If current raw contains warnings, explicit empty does not match. For every new attempt-scoped artifact, every event must contain an explicit warning array and it must match current raw exactly; a warning-only current-raw mutation invalidates details/download.

### Exact nonce and one-winner claims

Every modern harmony claim receives a durable 32-lowercase-hex `harmony_attempt_id`. Progress, failure, and completion require the exact stored nonce. Omitting `attempt_id` matches only a genuinelegacy processing row whose stored nonce is NULL; omission is not a wildcard for a nonce-bearing attempt.

`force=true` is valid for completed … computation on processing only. A second request while already processing conflicts and schedules no second worker.

### Attempt-scoped publication and processor-isolated isolation

Modern attempts publish only to:

```
harmony/harmonic-context.<32-lowercase-hex-attempt-id>.json
```

The durable exposed pointer may be either that strict attempt path or the backward-compatible legacy `harmony/harmonic-context.json`.

`_run_harmony_job()` executes the ***entire injected processor call*** inside `harmony_artifact_scope(expected_artifact_file_name)` while still passing the explicit `attempt_id`. Therefore an injected nonce-agnostic processor that internally calls `write_harmony_artifact(job_id, settings, payload)` without an explicit target is redirected to its own attempt file and cannot overwrite a previous legacy success. Nested scopes restore the outer target, and the ContextVar is reset on normal return and every exception. No guarantee depends on propagation into arbitrary child threads.

The default pipeline still explicitly selects its attempt-scoped filename, so isolation exists at both the generic worker boundary and built-in pipeline boundary.

### Durable pointer promotion and old/new worker interleaving

Only the exact active nonce may promote its matching attempt filename into durable job state. The permanent interleaving regression now uses a legitimate transition:

1. claim old attempt A;
2. successfully replace the canonical raw-transcription source, invalidating A and returning harmony to a claimable state;
3. claim newer attempt B;
4. B publishes and automatically promotes its nonce-matched target;
5. A finishes late.

The late A worker cannot mutate B's progress/status, promote a pointer, restore over B, delete B, fail B, or hide B. Its own non-durable target is cleaned and the complete durable B record remains unchanged; details/download continue to return B.

### Previous-result availability

A forced computation preserves the prior durable pointer. During computation and after failed/stale retries, summary/details/download continue to expose the prior validated success. Only after a newer success is automatically promoted may the superseded success file be removed best-effort; cleanup failure cannot change the new pointer.

### Post-replace rollback and crash durability

PR #99's exact-byte rollback remains target-scoped. If publication fails after `os.replace`, the writer restores the exact previous bytes or removes a first-unverified publication for that target.

Under the existing platform policy, ***every directory-entry mutation is now followed by directory fsync when supported***:

- recovery replace … directory fsync;
- first-publication recovery unlink … directory fsync;
- `_restore_harmony_artifact(previous=None)` unlink … directory fsync.

If the recovery directory sync fails, recovery failure is surfaced instead of reporting safe restoration. Temporary files remain best-effort cleaned. Windows retains the explicit no-directory-fsync policy; that limitation remains a declared residual rather than a stronger durability claim.

### Generic worker orphan reconciliation

Before ***any injected harmony processor*** runs, `_run_harmony_job()` reconciles the harmony directory using the database's durable artifact pointer and the database's exact current active attempt nonce.

It preserves:

- the legacy durable file;
- the durable current attempt file, if different;
- the exact live attempt target.

It removes only strict, contained, regular, non-durable, non-active `harmonic-context.<nonce>.json` files. Malformed attempt-looking names, symlinks, non-regular files, directory replacement, containment changes, and path races fail closed. The default pipeline reconciliation remains idempotent.

The repeated crash/restart/retry regression creates multiple pre-promotion attempt files, clears their nonces through restart recovery, then starts a live attempt. At the generic worker boundary the old orphans are reclaimed while the durable previous result and live attempt are preserved; no orphan accumulation survives the next worker execution.

### Legacy canonical path

Existing completed jobs that durably point to `harmony/harmonic-context.json` remain readable and downloadable through the same validation/storage contract. Modern nonce-bound attempts cannot promote that shared legacy filename.
